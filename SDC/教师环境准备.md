# 教师环境准备与故障排查

本页供教师/助教课前准备，学生从[学生操作手册](学生操作手册.md)开始。以下完整安装记录不是每个学生的必做清单，也不增加考核项。

## 1. 只为现有课程准备环境

| 时点 | 教师准备 | 学生需要做 |
|---|---|---|
| 课前一次 | 在课程机器上准备JDK17、Maven、IDEA/Git和依赖缓存，运行E1测试 | 打开mall并运行本次测试 |
| E1 | 用既有Compose启动样例环境、打包portal，验证一次商品查询 | 在准备好的课程机器上执行查询，说明请求经过哪些层 |
| E2、理论架构对照 | 准备mall-swarm源码截图或浏览器链接 | 阅读对照，无需clone、安装或部署swarm |
| E3/E4/E6 | 准备JavaEvidence与JaCoCo所需缓存，演示一次原版与当前版对照 | 使用个人分支完成本次小改动、测试并解释证据 |
| E7 | 准备一种模型访问方式和统一评测题，课前核对数据库期望 | 执行本次验收；故障时做离线检查并分析标明来源的真实结果 |

只克隆mall就能完成学生主路径。两个前端用于理论讲解/教师演示，不要求学生安装Node；swarm只作阅读材料。不得把前端打包、部署微服务、购买模型账号列为加分或提交条件。Compose现有四个依赖与portal启动配置配套，直接复用，不再引入一套环境脚本。课堂机器使用每台独立本地样例库，下面的loopback配置不是共享服务器配置，不向公网暴露服务。

沿用[课程考核方案](课程考核方案.md)的30%/70%权重、预习、3份互评、签到与访问要求；作品仍为一页说明和≤2分钟录屏。规格、图、AI使用与测试证据都放入同一份作品，代码差异作为附件，不另收长报告、日志大全或配置截图集。

**课前故障备用**：缓存Maven依赖（首次联网后才可离线）；准备有来源的原始对照/模型结果。学生本机故障可在已配好的课程机器操作。在线模型故障时保留“未完成在线验收”的状态，允许提交离线协议测试、失败原因与结果分析获得已有标准下可评分的证据；不得把替身或旧结果标为本人新跑的准确率。不承诺未执行部分通过，不另设分数权重。

## 2. 安装工具并验收环境

| 工具 | 配置与用途 | 安装依据 |
|---|---|---|
| Git | 2.x；下载、分支、差异、提交 | [官方安装](https://git-scm.com/downloads/) |
| JDK | **17**，不是只装 JRE；编译和运行 Java | [Temurin 安装](https://adoptium.net/installation/)；选择17及本机架构 |
| Maven | 3.9.x 或更新的兼容3.x；下载依赖、编译、测试 | [官方安装](https://maven.apache.org/install.html) |
| IntelliJ IDEA | 配置 Project SDK、Maven Importer、Runner 为17 | 用 IDE 打开根 `pom.xml` |
| Node.js/npm | 前端需要；推荐 Node22（至少22.12），或满足后台 `engines` 的版本 | [官方下载](https://nodejs.org/en/download)；不要套用旧版 Vue2 教程 |
| Docker Desktop + Compose v2 | 运行 MySQL、Redis、MongoDB、RabbitMQ | [官方安装入口](https://docs.docker.com/desktop/)；Windows 使用其 WSL2 后端，Mac 区分 Apple Silicon/Intel |
| RTK | 本课程仓库的命令前缀；JavaEvidence 工具和 Cursor 适配器也会调用它 | [项目安装说明](https://github.com/rtk-ai/rtk) |

Windows：JDK 安装后将 `JAVA_HOME` 指向 JDK17 根目录（不要以 `bin` 结尾），把 JDK 与 Maven 的 `bin` 放入用户 `Path`，重新打开终端。macOS/Linux 同样设置 `JAVA_HOME` 和 `PATH`，不照抄教师机器的绝对路径。Docker Desktop 必须处于运行状态。建议16GB内存；先完成离线实验，在线环境再为 Docker 分配约4GB以上内存。

下文终端命令统一保留 `rtk proxy`；它把后续命令交给原程序执行。未安装时，普通 Maven/npm/Git 命令可暂时去掉这个前缀，但 JavaEvidence 与 Cursor 路径仍需要真实 RTK。不要在终端输入 Markdown 的三个反引号。

```sh
rtk proxy git --version
rtk proxy java -version
rtk proxy mvn -version
rtk proxy node --version
rtk proxy npm --version
rtk proxy docker compose version
rtk proxy docker info
rtk --version
```

验收：Java 和 Maven 输出的 Java 版本均为17；Node 满足前述版本；Docker 能显示 Server 信息。仅 Docker 客户端版本正确但 `docker info` 连接失败，不算通过。保存版本截图，不截图任何密钥。

## 3. 教师仓库准备与 IDEA 导入

在文件管理器建立 `sdc-course` 文件夹，在该文件夹打开终端。四个仓库必须是同级目录，不要把前端克隆到 mall 内。

```sh
rtk proxy git clone --branch sdc-java-migration https://github.com/meng004/mall.git
rtk proxy git clone https://github.com/meng004/mall-admin-web.git
rtk proxy git clone https://github.com/meng004/mall-app-web.git
rtk proxy git clone https://github.com/meng004/mall-swarm.git
```

不要加 `--depth 1`：E3/E4/E6 的原版对照会读取历史提交。若以前克隆过，先看 `git status`，有未提交作业时先保存自己的分支，不重复覆盖目录。教师已有的 mall checkout 是复用后把 `origin` 指向教师 fork、`upstream` 保留原作者；学生新 clone 的 `origin` 应为 meng004。

本手册验证过的配套版本如下。需要重现本次前端结果时，在对应仓库执行 `rtk proxy git switch --detach <下表提交>`；把尖括号及其中说明替换成真实提交。准备修改代码时再创建个人分支。

| 项目 | 本次源码提交 |
|---|---|
| mall-admin-web | `81fc17e5a19f452bd854b106a9d59fa1ed5c7eac` |
| mall-app-web | `b1eb3cde1d74fbf62e72195bafd9322c8149f4c8` |
| mall-swarm | `04c442fe318356bae4445a109dde7af297ce1e84` |

在 **mall 目录**打开终端，建立自己的工作分支（把学号替换为本人学号）：

```sh
rtk proxy git switch -c student-学号
rtk proxy git remote -v
rtk proxy git rev-parse HEAD
```

IDEA 选择 Open → `sdc-course/mall/pom.xml` → 作为 Maven 项目打开；Project SDK、Maven Importer JDK、Maven Runner JRE 全设17，Reload All Maven Projects。等待依赖下载完成。应看见7个产品模块和 SDC 下7个实验模块。不要只打开 `SDC/E3` 导致它找不到产品依赖。

在 mall 目录运行：

```sh
rtk proxy mvn -Ddocker.skip=true clean package
```

首次需要网络，不加 `-o`。`-Ddocker.skip=true` 只跳过 Docker 镜像构建；SDC 自己的测试仍运行。不要加 `-DskipTests=true` 作为测试验收。预期16个 reactor 项目 SUCCESS、SDC 共32项测试通过；原产品模块按上游默认配置跳过其集成测试，不能把此结果称为整个商城已端到端验收。

## 4. 启动独立样例环境

工作目录：**mall**。先读清楚：上游 `document/sql/mall.sql` 含 `DROP TABLE`。下面的 Compose 只在新的 `sdc-classroom` MySQL 数据卷首次启动时导入它，不要手工导入已有业务数据库。

```sh
rtk proxy docker compose -f SDC/environment/compose.yml up -d
rtk proxy docker compose -f SDC/environment/compose.yml ps
rtk proxy docker compose -f SDC/environment/compose.yml logs --tail 30 mysql
```

首次初始化需要等待，日志中出现正常接收连接后再验收：

```sh
rtk proxy docker compose -f SDC/environment/compose.yml exec -T mysql mysql -umall -psdc-local-app mall -e "SELECT COUNT(*) AS visible_products FROM pms_product WHERE delete_status=0 AND publish_status=1;"
rtk proxy docker compose -f SDC/environment/compose.yml exec -T redis redis-cli ping
rtk proxy docker compose -f SDC/environment/compose.yml exec -T rabbitmq rabbitmqctl list_vhosts
```

原始样例可见商品为20条；Redis 返回 PONG；RabbitMQ 包含 `/mall`。公开的教学口令仅用于本机样例环境，不能复用到学校公网服务器。MySQL 的命令行口令提示在这里针对公开样例口令，不应据此把个人凭据放入命令行。

| 服务 | 本机地址/端口 | 配置 |
|---|---|---|
| MySQL8 | `127.0.0.1:13306` | 库 mall；应用账号 mall / sdc-local-app |
| Redis7 | `127.0.0.1:16379` | 无密码，仅本机映射 |
| MongoDB7 | `127.0.0.1:27018` | portal 使用 mall-port |
| RabbitMQ3.13 | `127.0.0.1:5673` | mall / mall，vhost `/mall` |
| RabbitMQ 管理页 | `http://127.0.0.1:15673` | mall / mall |

与上游默认端口不同是为了避免占用已有3306等服务；`SDC/environment/application-sdc.yml` 负责覆盖连接地址。四个容器不包含 Elasticsearch、MinIO 和支付沙箱，因此商品搜索引擎、图片上传与支付不在本手册运行验收范围。课程使用 portal 的 `/product/search`（MySQL查询），不是 mall-search 的全文搜索。

分别在两个 **mall 目录**终端启动服务，命令会持续占用终端：

```sh
rtk proxy java -jar mall-portal/target/mall-portal-1.0-SNAPSHOT-exec.jar --spring.config.additional-location=file:./SDC/environment/application-sdc.yml --server.port=18085
```

```sh
rtk proxy java -jar mall-admin/target/mall-admin-1.0-SNAPSHOT.jar --spring.config.additional-location=file:./SDC/environment/application-sdc.yml --server.port=18080
```

portal 用 `-exec.jar`，admin 用普通文件名。看到 Started 后，在第三个终端查询：

```sh
rtk proxy curl --noproxy '*' 'http://127.0.0.1:18085/product/search?keyword=HUAWEI%20P20&pageNum=1&pageSize=5'
```

验收：JSON 的业务 `code` 为200，`data.list` 包含商品26。不要只看 HTTP200。课程配置关闭 RabbitMQ 消费者自动启动，避免浏览商品时消费订单取消消息；因此此运行方式不证明异步订单流程。IDEA 也可运行 `MallPortalApplication` / `MallAdminApplication`，工作目录设 mall，Program arguments 使用对应的两个 `--` 参数。

结束时 Java 终端 Ctrl+C；中间件停止并保留数据：

```sh
rtk proxy docker compose -f SDC/environment/compose.yml stop
```

重开仍用 `up -d`。不要加 `down -v`，它会删除本课程数据卷；需要重做数据库时先备份，由教师指导。已存在数据卷时 SQL 不会重复导入。

## 5. 配套前端安装、配置和运行

先确保第4节 admin/portal 已启动。用编辑器创建本地环境文件，不提交密钥。

**后台前端**：在 `mall-admin-web` 根目录新建 `.env.development.local`，内容一行：

```dotenv
VITE_BASE_SERVER_URL=http://localhost:18080
```

在 **mall-admin-web** 目录运行：

```sh
rtk proxy npm ci
rtk proxy npm run build
rtk proxy npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

浏览器打开 `http://127.0.0.1:5174`，样例后台账号 `admin` / `macro123`。打开开发者工具 Network，确认登录请求发往 `localhost:18080/admin/login`，不要发到公网演示站。登录后查看商品列表，只做浏览；若失败，先查后端日志和接口地址，不通过删库重试。

**商城前端**：在 `mall-app-web` 根目录新建 `.env.development.local`：

```dotenv
VITE_API_BASE_URL=http://localhost:18085
VITE_USE_ALIPAY=false
```

在 **mall-app-web** 目录运行：

```sh
rtk proxy npm ci
rtk proxy npm run build:h5
rtk proxy npm run dev:h5 -- --host 127.0.0.1 --port 5173 --strictPort
```

打开 `http://127.0.0.1:5173`，开发者工具切换手机视图；先浏览首页和商品，不下单、不支付。验收 Network 中请求指向18085，记录一次请求 URL、响应字段及后端入口。图片可能依赖外部地址，图片失败不等于商品接口失败。H5 构建输出位于 `dist/build/h5`；后台构建输出位于 `dist`。

两者保留 package-lock，优先 `npm ci`，不要为消除警告擅自执行 `npm audit fix --force`。更改 `.env` 后重启 Vite。浏览器使用上面的 `127.0.0.1` 地址，与启动绑定地址一致；`localhost` 可能优先解析为 IPv6，误连到另一个已有服务。本次实际使用 Node26 构建通过；Node22符合后台声明的兼容范围，但本次未另做 Node22 的构建复测。样式弃用、打包体积警告须与真正的编译错误区分。


## 6. 课堂产出与模型准备

E1/E2/E5只要求分析，不要求修改业务代码。E3/E4/E6只修改本次业务点，不改生成代码/数据库表/公开接口；不要扩成商城开发。E6必须包含既有方案要求的两套规范取舍，不另写规范比较论文。

E7沿用已有只读接口与访问层，按[E7操作说明](E7/操作说明.md)选择一种模型接入；不要同时要求学生申请多家服务。使用课程Compose时，IDEA工作目录设mall，环境变量 `SPRING_CONFIG_ADDITIONAL_LOCATION=file:./SDC/environment/application-sdc.yml`。题集与对抗用例由教师/助教一次准备（考核方案第六节），学生解释构造思路与验收结论，无需人人另造32题。新题的期望用当前样例库只读SQL核对；公开旧题只能回归。已记录31/32，不宣称100%。

原版综合对照命令见[E3操作说明](E3/操作说明.md)，只在教师完整参考分支运行，全课只准备一次工具与缓存。个人E3分支使用该页单独采集E3覆盖率的两条命令；E4/E6各跑本实验，不能被其他实验的原版失败阻断。原版E3两处积分断言、E6缺失告警失败；E4原版就通过。JavaEvidence会写同名证据文件，学生把本人输出另存到作业附件并说明来源，不能覆盖教师首次证据后混称原记录。

本轮只是缩减学生必做环境和重复交付，不改测试断言、只读限制、凭据处理或模型解析协议。浏览器/构建实测范围见[发布验收](发布验收.md)。
