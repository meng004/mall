## Standards：边界与证据规范发现

### S1 / P1：属性值没有得到原文支持，重复属性能使评测崩溃

[ExistingAttributeExtractionService.java](../../.worktrees/sdc-integrated/mall-portal/src/main/java/com/macro/mall/portal/ai/attributes/ExistingAttributeExtractionService.java)第64–88行只查证据子串存在、候选值在允许集合中，没有检查两者是否相符，也未拒绝重复属性或已知/未知冲突。实际调用编译后的真实类：输入“蓝色”、允许红/蓝，返回`红，evidence=蓝色`得到`OK`；同ID蓝/红两个结果也得到`OK`。随后`CandidateE705Evaluation.matches`第30行`toMap`抛`Duplicate key 21`，比较发生于业务调用的try/catch之外，最终报告可能完全不写。

违反原计划“原文未支持则未知”与证据完整性要求。[复现源及结果](evidence/cursor-review/SdcAttributeProbe.log)。修复应放在现有`check`及现有比较器，不增加独立校验平台。

### S2 / P2：三个比较器将合法证据片段误当成唯一答案

`CandidateE704Evaluation`第80行、E705第106–107行、E706第129/166–172行要求证据字符串逐字相等。原计划要求语义结果正确、原文确有支持，不要求引用唯一片段。应区分主题/值/计数错误与引用措辞差异，不能仅放宽为“任意原文子串”——S1说明子串存在本身也不够。

E7-05公开N02结果为`OK`且输出蓝/256GB，却判失败，符合此类误判特征；本次未读取其expected，具体原因仍需用已公开案例离线复评确认。E7-04 N10漏掉被讨论的QUALITY可能是真错误，不能把所有失败都归咎比较器。

### S3 / P2：最终说明、报告与索引尚未形成一致的可查记录

- E7-04说明第3/33行仍写“真实模型未运行”，第37行起又记录已跑32题。其他题也需检查这种阶段记录冲突；历史状态应标日期，当前结论只保留一份。
- E704/05/06报告主要保存state和模型原文，缺少Java最终规范化结果及具体失败字段，读者无法直接定位模型、解析、转换还是比较器的问题。
- `EvaluationSupport`第23/134/135行把“课程离线测试已通过”“供应商未返回usage”写成常量，当前CLI适配器只返回文本；这些字段本身不是每次运行的证明。成本写“无数据”是诚实的，缺失原因应写“当前适配器未暴露”，除非另有供应商响应证据。
- 7处说明到mall-admin测试文件的链接少一级`../`：E1-05、E5-01/02/06、E6-01/02/06。批量索引中worktree路径仅为代码文字，且不是相对索引位置的可点击链接。

## Spec：功能与验收要求发现

### F1 / P1：E3-04属性迁移的三次写入无事务

`PmsProductAttributeServiceImpl.update`第82/99/101行分别更新属性、旧分类、新分类。接口第31行无`@Transactional`，同接口create/delete已有该注解；Spring事务属性解析结果为`null`。后续计数写异常会使归属与计数不一致。已证实缺少声明式事务，尚未用真实数据库制造部分提交；后者是修复验收要求，不能用Mock宣布回滚成功。[探针结果](evidence/cursor-review/SpecProbe.log)。

### F2 / P1：E6-04集成测试会触及非本次创建的数据

`SDCE604MongoTest`第52/57–64行固定会员101与截止时间，调用`clearBefore`会删除该会员所有早期记录。随机文档ID及finally只清理插入ID不能阻止或恢复这种误删。**连接Mongo重跑前先隔离本测试数据库/会员**。本次没有执行删除；风险来自确定的查询范围，不能说已经发生数据损失。

### F3 / P2：E3-03全部ID不存在时生成非法SQL

`PmsProductAttributeServiceImpl.delete`第123–125行在`existingById`为空时仍执行`andIdIn`。使用实际生成Mapper的MyBatis渲染结果为`delete from pms_product_attribute WHERE ( id in )`。现有混合ID测试未覆盖全不存在场景。应返回0且不删除、不调整计数，不修改生成Mapper。[探针结果](evidence/cursor-review/SpecProbe.log)。

### F4 / P2：E3-01小额优惠券仍被错误拒绝

`UmsMemberCouponServiceImpl`第180/200行保留`intValue()>0`。真实`listCart`在分类/商品匹配额0.90、门槛0.50、有效期内返回可用数0，期望1。Cursor已经披露此残留，说明诚实，但修复仍不完整。[探针结果](evidence/cursor-review/CouponProbe.log)。

### F5 / P1：E7-01/02的“缺库”被写死在评测入口

E701第87–89行、E702第75–81行固定`isolated=false`，依赖使用必定抛异常的`EvaluationSupport.unavailable`。因此**仅启动MySQL、装入数据仍无法完成验收**；必须接入真实受控Spring服务/Mapper，建立教学会员身份并加载facts。不能把这项只列为用户环境阻塞。

### F6 / P2：必需的真实环境证据仍缺失

E1要求一次真实只读商品查询；E6-02要求真实筛选与分页；E6-04/05要求Mongo删除/筛选条数；E7-01/02要求身份和可见性边界的库证据。这些尚未完成。不能反过来要求每道E2/E4都新增HTTP/数据库验收：原计划允许用局部观察证明相应范围，避免扩大课程任务。

## 超时的可证实范围

公开记录约60019–60045毫秒停止，与`EvaluationSupport.cursorClient`固定60秒上限相符。当前证据只能证明截止时间触发，不能判定网络、供应商故障、登录失效或模型推理慢。`CursorCliLlmClient`第41行丢弃stderr，诊断信息不足。

有的输出带“先核对仓库”等解释文字，违反严格JSON协议；适配器已有独立临时workspace及工具deny配置，这句话不能证明读取了仓库或泄漏答案。计划要求用非验收探针检查CLI实际行为，保持严格JSON，不截取第一个大括号来掩盖失败。

## 交付判断

Standards轴3组发现，最严重为无依据值被接受及报告可能丢失；Spec轴6组发现，最严重涉及数据一致性、测试删除范围和无法接通的真实评测。不存在为代码异味单独增加抽象的必要。

42份产出可作为“已实施、部分验证”的成果；207项通过是真实但有限的证据。模型暂不放行是正确结论，现有分数须注明比较器待修正。无人工核对和录屏已如实披露，这部分不得由代理冒充完成。后续执行见[Cursor修复与复验计划](Cursor产出修复与复验计划.md)。
