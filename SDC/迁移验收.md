1. **Boot 可执行 JAR 不能作为实验编译依赖。** 已复现 `package` 阶段缺少 portal 类的编译失败；改为普通主 JAR + `-exec.jar` 可执行附件。完整 `clean package` 通过。Docker 构建归档验证容器仍获得可执行 JAR，原镜像入口与容器文件名保留；未构建或发布镜像。
2. **只读演示不能自动消费订单取消消息。** 在演示和评测共同入口关闭 RabbitMQ simple/direct listener 自动启动。真实查询验证期间未调用订单、库存或成员写业务。

## E7 新独立评测

独立人员未读取 E7 实现、提示词、测试和旧题集；通过只读 SQL 单独推导20条正常查询的期望 ID，另编8条对抗、4条分布外请求。实现者在运行前未读取新题。

第一轮真实 Cursor → Java → MySQL 得到30/32：正常18/20、对抗8/8、分布外4/4。原始[题集](E7/evaluation/java-holdout-1.json)、[结果](E7/evaluation/java-holdout-1-result.json)与[日志](evidence/java-migration/holdout-1.log)保留。两条失败是名称包含字面 `%` 和 `_`：模型输出正确，Java 条件校验错误拒绝。诊断结果在 `java-holdout-1-diagnosis.json`。

已在共同 SQL 查询入口对新结构化名称转义，保留旧六参数搜索行为；没有修改提示词。新增 JUnit 先复现失败，再验证百分号、下划线和反斜杠在两种实现中的字面语义。两条真实模型回归均通过，记录在[回归结果](E7/evaluation/java-holdout-1-regression.json)和[日志](evidence/java-migration/holdout-1-regression.log)。已公开的这两题只算回归，不再算独立新题。

第二套独立32题由同一独立人员另行编制，其未接触实现、提示词或第一轮失败详情；运行期间未修改实现或提示词。2026-10-03 使用本机 Cursor 登录、`grok-4.7-high-fast`、真实 Java 服务与现有 MySQL 执行，结果为 **31/32（96.875%）**：正常19/20、对抗8/8、分布外4/4。题集的预期 ID 来源为独立只读 SQL。[题集](E7/evaluation/java-holdout-2.json)、[来源方法](E7/evaluation/java-holdout-2-method.md)、[原始结果和模型输出](E7/evaluation/java-holdout-2-result.json)、[运行日志](evidence/java-migration/holdout-2.log)均保留。

唯一失败 `holdout2-n09`：模型在正确的 `{"action":"query","stock_lt":501}` 前夹带了工作区查找说明，应用按既有严格 JSON 协议拒绝，返回 `UNSUPPORTED`。这是模型输出协议偏离导致正常请求误拒绝，没有修改解析规则来凑通过。评测器因此输出 `FAILED` 并退出1；不能称为全部通过。

对抗和分布外统计是**应用端到端结果**，不是模型自身完全遵守指令的比例：部分原始模型响应包含菜谱、代码等范围外内容，Java 校验将其拒绝且没有作为业务结果返回。模型有尝试寻找工作区数据的叙述；该文字不证明工具被执行，CLI 空临时目录与 deny 权限边界仍保留。小样本、单模型、单次运行结果不能外推生产准确率。

## 局限

单元测试不证明数据库事务、并发订单或消息可靠性；E1/E2/E5 的字面源码检查不是 Java/SQL 语义分析器。教师或学生变更样例库后，在线题集的期望 ID 需要重新独立核对。

Cursor 路径依赖已安装并登录的官方 CLI；通用 API 路径通过本地 HTTP 服务验证了实际 SDK 协议，但尚未对其他厂商在线端点逐一验收。API 登录 token 必须由对应服务接受，不能与 Cursor 登录态混用。

IDEA 导入与断点步骤已提供，未执行 IDEA 图形界面的课堂操作验收；本次验证使用标准 Maven 工程与真实 Java 入口。
