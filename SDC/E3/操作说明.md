## 规格

作为下单者，我希望同一订单分别保存消耗积分与赠送积分，以便支付、取消及后续核对。

验收准则：使用30、赠送12时，真正调用 `OmsOrderMapper.insert` 的参数必须含 `useIntegration=30`、`integration=12`；未使用时消耗保持null，明确使用0时保存0。无效地址、库存不足、优惠券不可用不能继续下单。

不可变约束：不改 `mall-mbg`、表结构、Mapper插入调用与公开服务接口；外部数据库/Redis/消息可在单元测试中替换，业务服务必须实际执行。

覆盖率口径：`generateOrder` 方法行和分支均至少80%，另逐项断言三种积分输入的插入快照；禁止用Python断言数充当Java覆盖率。

## IDEA 演示

导入 `mall/pom.xml`，Project SDK 和 Maven Runner JRE 均设为 JDK 17，重新加载 Maven。
打开 `E3/src/test/java/com/macro/mall/sdc/e3/OrderIntegrationTest.java`，点击类旁运行按钮。可在真实 `mall-portal` 业务方法设断点，再 Debug 此测试。测试只替换数据库、Redis、消息等外部依赖，不执行另写的业务副本。

## Maven 复现

以下命令工作目录为 `mall`；先确认 `java -version` 和 `mvn -version` 使用 JDK 17。Maven 首次运行需要网络下载依赖。

```bash
rtk proxy mvn -pl SDC/E3 -am test
```

原项目默认跳过自己的测试；SDC 已启用测试。该命令不要求启动 MySQL、Redis 或消息队列。

## 个人E3分支的覆盖率（只测本实验）

完成积分修复后，在mall目录运行；不要要求尚未完成的E6也通过：

```sh
rtk proxy mvn -pl SDC/E3 -am clean org.jacoco:jacoco-maven-plugin:0.8.13:prepare-agent test
rtk proxy mvn -pl mall-portal -Djacoco.dataFile=../SDC/E3/target/jacoco.exec org.jacoco:jacoco-maven-plugin:0.8.13:report
```

先确认E3四项通过，再打开 `mall-portal/target/site/jacoco/index.html`，进入 `OmsPortalOrderServiceImpl` 的 `generateOrder`。按该方法看行与分支（均至少80%），不以整个类的百分比代替。第一条clean用于本次独立采集，第二条读取E3执行数据，不运行E6；不要在两条命令之间改源码。机器第一次需要联网下载JaCoCo，课前缓存后可以离线。

## 教师参考分支的原版与当前版综合对照

以下综合命令只供教师在完整参考分支核对历史，不作为个人E3分支的覆盖率入口。

在联网完成一次依赖准备后，Java 工具采用离线 Maven 运行；JaCoCo 依赖首次准备：

```bash
rtk proxy mvn -pl SDC/E3,SDC/E4,SDC/E6 -am org.jacoco:jacoco-maven-plugin:0.8.13:prepare-agent test
rtk proxy java SDC/tools/JavaEvidence.java --original
rtk proxy java SDC/tools/JavaEvidence.java
```

工具在临时目录复制构建所需源码，以原提交的订单/促销服务替换相应文件，运行后清理临时目录。它不回滚工作区。原版预期：E4 通过，E3 两个积分插入断言失败，E6 一个缺失告警断言失败；Maven 编译错误或测试运行错误不视为红灯证据。当前版应全部通过。

日志与当前 JaCoCo XML 写入 `SDC/evidence/java-migration/`。历史运行保留在 `SDC/java-evidence/`，不混用测试计数或覆盖率。新开实验仍应按“规格→失败测试→实现→审查→验证”演示；重建原版不是历史上已执行测试先行的证明。
