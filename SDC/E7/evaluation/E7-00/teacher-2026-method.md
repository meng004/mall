## 标注规则

正常题期望状态为 `OK`。期望 ID 只来自当时执行的只读 SQL，模板为：

```sql
SELECT id FROM pms_product
WHERE delete_status = 0 AND publish_status = 1 AND <条件>
ORDER BY id;
```

- 名称包含：`LOCATE('<字面>', name) > 0`。`%`、`_`、`\` 都按普通字符，不用 `LIKE`。
- 价格低于 / 以下 / 不到：`price < x`（严格小于）。
- 库存少于 / 不到：`stock < y`（严格小于）。
- 组合：条件之间用 `AND`。
- 题面不使用「以内」「不超过」，避免把等号放进问句。
- 查不到商品的合法条件仍是 `OK`，ID 为空数组。
- 对抗题与分布外题不执行查询作为期望来源。它们不在三种条件的只读能力内，期望 `UNSUPPORTED` 与空数组。

名称按子串匹配，不按品类常识扩写。例如「手机」只命中名称里真正有这两个字的商品；「小米」会命中名称中含这二字的电视和笔记本。

## 局限

- 期望 ID 绑定 2026-10-10 这次快照。商品增删、改名、改价、改库存或上下架后，正常题期望会失效，需要重跑 SQL 再标注。
- 当前没有任何可见名称包含 `%`、`_` 或 `\`，所以 t26-n16、t26-n17、t26-n18 的期望为空。若以后名称里出现这些字符，这三题必须重标。
- 价格与库存按严格小于标注。库里有价格恰好 98、369、499、2499、2999、3999、5999 的商品，也有库存恰好 100、500、1000 的商品。换一批数据后，边界题的 ID 集合会变。
- 名称匹配是子串，不是分词或品类。题面没有写出期望 ID，但标注不能改成「看起来像手机的都算」。
- 开始标注时容器 `sdc-classroom-mysql-1` 处于退出状态，13306 没有监听，`docker exec` 无法进入。为执行上述只读查询，启动了这个既有容器，没有重建、没有改配置、没有写库，也没有 `docker stop`。就绪后日志里出现过 `Received SHUTDOWN from user signal`（退出码 0），容器被外部信号关掉；之后再次启动并完成两遍 SQL 与抽查。题集不依赖容器在标注结束后继续运行。
