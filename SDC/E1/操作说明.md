# E1 开发环境与棕地仓库导读

教学仓库：[meng004/mall](https://github.com/meng004/mall/tree/sdc-java-migration)，分支 `sdc-java-migration`。原版分析参照上游提交 `dcaa93b3150352e5044708d7211b5bed0af4509f`；当前行号以源码为准。本次不改 `mall` 里的业务代码，也不改 `mall-mbg` 的生成代码。

## 目标

1. 读出七个模块各做什么，以及 `pom.xml` 里的直接依赖。
2. 标出生成代码边界：`mall-mbg`。
3. 顺着 `mall-portal` 的“下单 → 支付 → 超时取消”走一遍，写出经过的类和数据方向。

## 前置条件

- JDK 17、Maven；在 IDEA 中作为 Maven 项目打开 `mall/pom.xml`，Project SDK 和 Maven Runner JRE 均选择 JDK 17。
- 源码工具和 JUnit 不需要中间件；完整环境验收另需 mall 开发配置对应的中间件。
- 图在 `SDC/E1/diagrams/`：`mall-runtime.html`（运行路径）、`mall-modules.html`（模块职责）、`mall-classes.html`（类协作）、`mall-dependencies.html`（直接依赖）。模块图只画代表关系；八条直接依赖是当前演示观察值，以 main 输出和源码为准，测试只验证解析规则。

## 核心步骤

1. 打开根 `mall/pom.xml` 的 modules，确认七个产品模块与新增的 SDC 聚合模块。再打开每个模块的 `pom.xml`，只记录 `groupId` 为 `com.macro.mall` 的依赖。
2. 打开 `mall-mbg/src/main/resources/generatorConfig.xml`。这个模块是 MyBatis Generator 的产物，导读时只标边界，不改生成的 `OmsOrderMapper.java`。
3. 下单：`OmsPortalOrderController.java:43-45` 调用 `generateOrder`。服务实现在 `OmsPortalOrderServiceImpl.java:230` 插入订单，同文件 `:250` 调用 `sendDelayMessageCancelOrder`。
4. 支付：控制器 `:51-52` 调用 `paySuccess`。服务在 `:258-272` 把状态改为待发货，`:268` 调用 `PortalOrderDao.updateSkuStock`（接口在 `PortalOrderDao.java:22`），`:272` 返回更新行数。
5. 超时取消：`CancelOrderSender.java:25` 把订单发到 TTL 队列。`RabbitMqConfig.java:51-53` 到期后转发到 `mall.order.cancel`。`CancelOrderReceiver.java:16-23` 收到后调用 `portalOrderService.cancelOrder`。
6. 不要把 `POST /order/cancelOrder` 当成“立刻取消”。控制器 `:67-68` 只调用 `sendDelayMessageCancelOrder`。用户立刻取消走的是 `:95-96` 的 `/cancelUserOrder`。
7. 运行核对：

```bash
rtk proxy mvn -f mall/pom.xml -pl SDC/E1 -am test
```


## 当前 Java 入口

测试命令从包含 `mall` 的工作区运行；若已经在 `mall`，去掉 `-f mall/pom.xml`。首次构建允许 Maven 下载依赖，缓存齐备后可加 `-o`。

IDEA 打开 `SDC/E1/src/test/java` 下的 `MallFactsTest` 运行 JUnit；打开 `src/main/java/com/macro/mall/sdc/e1/MallFacts.java` 运行 `main`，在解析/定位方法设断点。演示会读取当前仓库并输出结果；JUnit 使用临时受控文件验证行为。

`main` 从工作目录向上查找含 `pom.xml` 与 `mall-portal` 的 mall 根目录，也支持工作区下的 `mall`。IDEA 工作目录可选 mall 或实验目录；任意目录启动时在 VM options 设置 `-Dmall.root=/你的路径/mall`（也接受 E 模块目录）。E2/E5 通过 Maven 依赖复用 E1 工具，IDEA 自动加入 classpath。

这些工具只做只读源码辅助检查，不是 Java/SQL 语义分析器：源码匹配依赖字面格式，注释和改名可能影响结果，需人工复核；不能用静态结果证明数据库事务、支付或消息行为。POM 只读项目直接声明依赖，不计算 profile、依赖管理或传递依赖。旧分析中的行号是历史快照。

## 真实构建与运行

在 `mall` 目录运行；先将 JAVA_HOME 指向本机 JDK 17，并使 `java -version` 显示 17。

```bash
rtk proxy mvn -B -DskipTests=true -Ddocker.skip=true compile
rtk proxy mvn -B -pl mall-portal -am -DskipTests=true -Ddocker.skip=true package
rtk proxy java -jar mall-portal/target/mall-portal-1.0-SNAPSHOT-exec.jar --server.address=127.0.0.1 --server.port=18085 --spring.rabbitmq.listener.simple.auto-startup=false --spring.rabbitmq.listener.direct.auto-startup=false
```

启动命令占用当前终端，另一个终端执行只读查询：

```bash
rtk proxy curl --noproxy '*' 'http://127.0.0.1:18085/product/search?keyword=HUAWEI%20P20&pageNum=1&pageSize=5'
```

首次准备E3/E4/E6测试依赖，在 `mall` 目录执行：

```bash
rtk proxy mvn -B -pl SDC/E3,SDC/E4,SDC/E6 -am test
```

保留原有数据库，不重新导入或清空数据。当前实验只读查询不需要创建订单；需要做交易端到端测试时应另用隔离数据。

## 评审记录

对照源码审过操作说明，删掉了没有行号的说法。三处和实验方案原文不一致，以仓库为准：

- `mall-mbg/pom.xml:22-25` 直接依赖 `mall-common`。方案只写了 security 依赖 common。这是方案没写全，不是仓库缺陷。
- `mall-search` 和 `mall-demo` 只依赖 `mall-mbg`，不依赖 `mall-security`。
- `OrderTimeOutCancelTask.java:14` 的 `@Component` 被注释掉，定时扫描当前不会注册成 Bean。正在生效的超时取消是延迟队列，不是这个定时器。这是设计残留。
