## 必须修复的发现

以下源码路径均相对集成 worktree。

### F1 / P1：新增 stderr 诊断会泄露部分凭据值

`mall-portal/src/main/java/com/macro/mall/portal/llm/CursorCliLlmClient.java:88–99` 仅将 `password`、`token`、`secret`、`credential` 单词替换，未删除其后的值。合成输入 `password=DUMMY_REVIEW_ONLY_83 token=DUMMY_REVIEW_ONLY_83` 调用真实 `stderrSummary` 后仍保留哨兵值，探针输出 `synthetic-secret-value-retained=true`。没有使用或暴露真实凭据。

触发链是 CLI stderr 带键值凭据 → diagnosis → 异常文本 → 评测 error/持久日志；现有测试只检查文字 `secret` 不出现，不能证明值被脱敏。修复属于履行已有脱敏合同，不新增安全门禁。`IOException` 消息路径第 71–72 行也只替换名称，应一起复用同一处处理。

### F2 / P2：回放修好了，在线入口仍把传输失败当成业务计分项

`CandidateE704Evaluation.java:100`、`CandidateE705Evaluation.java:151`、`CandidateE706Evaluation.java:183` 在在线传输失败时构造 `Score.fail("transport", "传输", error)`；`Score.fail` 的 `scored=true`，后续计入正常题分母。现有 `tallyLlm` 只识别“传输未完成”，对该真实结构的探针得到“可评分失败=1、传输未完成=0”。这不推翻已保存的 N12 回放归因，但下一轮在线报告会再次出现旧问题。

这三个在线入口也没有像回放一样输出完整题量分项。应在现有 Score/报告辅助方法和调用点统一口径，不再让回放承担纠正新报告的责任。

### F3 / P2：待人工未完成仍可能被写成质量不放行，正式放行条件未接入人工状态

`CandidateE704Evaluation.java:130`、E705:189、E706:223 调用 `decision` 时，仅将 `stopped` 作为 blocked；待人工样例被排除出正常计数，却不标 blocked。探针模拟 20 正常题中 1 条待人工、其余 19 条通过且 12 边界通过：在线调用路径返回 `NO_RELEASE`，同参数辅助 `verdict` 返回 `INCOMPLETE`。codeVerdict 与中文虽已同源映射，但入口对“是否完成”的推导仍不一致。

此外 `EvaluationSupport.java:482` 固定写“独立人工核对尚未进行”，`decision` 在 20 正常、18 通过、边界全过时却可返回“放行”。当前六题没有实际出现误放行，风险在下一次完整评测：报告可同时写无人核对和正式放行。必须履行上一轮已要求的“必需人工未完成→未完成”，复用现有报告状态；可以展示客观阈值已达成，但不能冒充人工完成。

### F4 / P2：已提交索引的 12 个 Markdown 链接全部失效，数据库测试口径误标

`SDC/候选靶点批量验收结果.md:7–17` 沿用 `../../.worktrees/sdc-integrated/...`：从主目录副本可用，从集成树中的已提交索引解析，会指向 `.worktrees/.worktrees/sdc-integrated/...`。独立解析结果 12/12 不存在。

第 15 行的“数据库测试 14/0/0 与 9/0/0”实际对应 SDCE701Test、SDCE702Test 的离线/替身及断库用例；真实数据库核对是 `CandidateDatabaseTest` 的 1 项，历史日志 full-offline 第 1543 行可查。总 262 没错，错在测试类型标签。另需补当前 E7-05 行，并区分代码受测版本 `206f2664` 与证据提交 `5d4920fc`。无需让提交引用自身新 SHA，采用受测提交号和 Git 历史即可。
