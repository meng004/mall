# SDC 学生操作手册：从克隆仓库到 E1–E7 验收

适用对象：学过 Java、SQL、HTTP 和 Git 基础的大三本科生。SDC 指 **software design and conventions**。本手册配合[课程实验方案](课程实验方案.md)，每次实验2学时；安装、首次下载依赖和模型登录应在课前完成。

## 1. 先弄清要运行什么

本课程在已有商城中读代码、写规格、做小范围改动。`mall` 是产品，`mall/SDC/E1` 到 `E7` 是实验入口；实验测试调用真实产品类。仓库已包含教师参考实现，直接运行成功只证明你能复现，不等于完成自己的设计和修改。

| 仓库 | 用途 | 本课程要求 |
|---|---|---|
| [meng004/mall](https://github.com/meng004/mall) | Java 后端、SDC 实验、手册 | 必须；教学分支 `sdc-java-migration` |
| [meng004/mall-admin-web](https://github.com/meng004/mall-admin-web) | Vue3 管理后台，连接 mall-admin | E1 界面导读与前后端请求追踪 |
| [meng004/mall-app-web](https://github.com/meng004/mall-app-web) | uni-app/Vue3 商城，H5 连接 mall-portal | E1 商品浏览与请求追踪 |
| [meng004/mall-swarm](https://github.com/meng004/mall-swarm) | 微服务版商城 | E2 架构对照，只需读源码，不是 E1–E7 的启动依赖 |

这些是教师账号下的上游 fork，原作者、许可证与 Git 历史保留。LangChain4j 是 Maven 依赖，无需克隆其源码；筛选报告里被排除的其他商城无需下载。

按三层推进：①离线 Java 测试，不启动 Docker、不调用模型；②本地中间件与前后端，只使用样例数据；③E7 在线模型，需要自己的有效 API 凭据或已登录的 Cursor。无在线账号时可以完成离线部分，但不能声称完成在线效果验收。

## 2. 安装工具并验收环境

| 工具 | 配置与用途 | 安装依据 |
|---|---|---|
| Git | 2.x；下载、分支、差异、提交 | [官方安装](https://git-scm.com/downloads/) |
| JDK | **17**，不是只装 JRE；编译和运行 Java | [Temurin 安装](https://adoptium.net/installation/)；选择17及本机架构 |
| Maven | 3.9.x 或更新的兼容3.x；下载依赖、编译、测试 | [官方安装](https://maven.apache.org/install.html) |
| IntelliJ IDEA | 配置 Project SDK、Maven Importer、Runner 为17 | 用 IDE 打开根 `pom.xml` |
| Node.js/npm | 前端需要；推荐 Node22（至少22.12），或满足后台 `engines` 的版本 | [官方下载](https://nodejs.org/en/download)；不要套用旧版 Vue2 教程 |
| Docker Desktop + Compose v2 | 运行 MySQL、Redis、MongoDB、RabbitMQ | [官方安装入口](https://docs.docker.com/desktop/)；Windows 使用其 WSL2 后端，Mac 区分 Apple Silicon/Intel |
| RTK | 本课程仓库的命令前缀；JavaEvidence 工具和 Cursor 适配器也会调用它 | [项目安装说明](https://github.com/rtk-ai/rtk) |

Windows：JDK 安装后将 `JAVA_HOME` 指向 JDK17 根目录（不要以 `bin` 结尾），把 JDK 与 Maven 的 `bin` 放入用户 `Path`，重新打开终端。macOS/Linux 同样设置 `JAVA_HOME` 和 `PATH`，不照抄教师机器的绝对路径。Docker Desktop 必须处于运行状态。建议16GB内存；先完成离线实验，在线环境再为 Docker 分配约4GB以上内存。

下文终端命令统一保留 `rtk proxy`；它把后续命令交给原程序执行。未安装时，普通 Maven/npm/Git 命令可暂时去掉这个前缀，但 JavaEvidence 与 Cursor 路径仍需要真实 RTK。不要在终端输入 Markdown 的三个反引号。

```sh
rtk proxy git --version
rtk proxy java -version
rtk proxy mvn -version
rtk proxy node --version
rtk proxy npm --version
rtk proxy docker compose version
rtk proxy docker info
rtk --version
```

验收：Java 和 Maven 输出的 Java 版本均为17；Node 满足前述版本；Docker 能显示 Server 信息。仅 Docker 客户端版本正确但 `docker info` 连接失败，不算通过。保存版本截图，不截图任何密钥。

在文件管理器建立 `sdc-course` 文件夹，在该文件夹打开终端。四个仓库必须是同级目录，不要把前端克隆到 mall 内。

```sh
rtk proxy git clone --branch sdc-java-migration https://github.com/meng004/mall.git
rtk proxy git clone https://github.com/meng004/mall-admin-web.git
rtk proxy git clone https://github.com/meng004/mall-app-web.git
rtk proxy git clone https://github.com/meng004/mall-swarm.git
```

不要加 `--depth 1`：E3/E4/E6 的原版对照会读取历史提交。若以前克隆过，先看 `git status`，有未提交作业时先保存自己的分支，不重复覆盖目录。教师已有的 mall checkout 是复用后把 `origin` 指向教师 fork、`upstream` 保留原作者；学生新 clone 的 `origin` 应为 meng004。

本手册验证过的配套版本如下。需要重现本次前端结果时，在对应仓库执行 `rtk proxy git switch --detach <下表提交>`；把尖括号及其中说明替换成真实提交。准备修改代码时再创建个人分支。

| 项目 | 本次源码提交 |
|---|---|

| mall-app-web | `b1eb3cde1d74fbf62e72195bafd9322c8149f4c8` |

在 **mall 目录**打开终端，建立自己的工作分支（把学号替换为本人学号）：

```sh
rtk proxy git switch -c student-学号
```

## 4. 启动独立样例环境

工作目录：**mall**。先读清楚：上游 `document/sql/mall.sql` 含 `DROP TABLE`。下面的 Compose 只在新的 `sdc-classroom` MySQL 数据卷首次启动时导入它，不要手工导入已有业务数据库。

```sh
rtk proxy docker compose -f SDC/environment/compose.yml up -d
rtk proxy docker compose -f SDC/environment/compose.yml ps
rtk proxy docker compose -f SDC/environment/compose.yml logs --tail 30 mysql
```

首次初始化需要等待，日志中出现正常接收连接后再验收：

```sh
rtk proxy docker compose -f SDC/environment/compose.yml exec -T mysql mysql -umall -psdc-local-app mall -e "SELECT COUNT(*) AS visible_products FROM pms_product WHERE delete_status=0 AND publish_status=1;"
rtk proxy docker compose -f SDC/environment/compose.yml exec -T redis redis-cli ping
rtk proxy docker compose -f SDC/environment/compose.yml exec -T rabbitmq rabbitmqctl list_vhosts
```

原始样例可见商品为20条；Redis 返回 PONG；RabbitMQ 包含 `/mall`。公开的教学口令仅用于本机样例环境，不能复用到学校公网服务器。MySQL 的命令行口令提示在这里针对公开样例口令，不应据此把个人凭据放入命令行。

| 服务 | 本机地址/端口 | 配置 |
|---|---|---|
| MySQL8 | `127.0.0.1:13306` | 库 mall；应用账号 mall / sdc-local-app |
| Redis7 | `127.0.0.1:16379` | 无密码，仅本机映射 |
| MongoDB7 | `127.0.0.1:27018` | portal 使用 mall-port |
| RabbitMQ3.13 | `127.0.0.1:5673` | mall / mall，vhost `/mall` |
| RabbitMQ 管理页 | `http://127.0.0.1:15673` | mall / mall |

与上游默认端口不同是为了避免占用已有3306等服务；`SDC/environment/application-sdc.yml` 负责覆盖连接地址。四个容器不包含 Elasticsearch、MinIO 和支付沙箱，因此商品搜索引擎、图片上传与支付不在本手册运行验收范围。课程使用 portal 的 `/product/search`（MySQL查询），不是 mall-search 的全文搜索。

分别在两个 **mall 目录**终端启动服务，命令会持续占用终端：

```sh
rtk proxy java -jar mall-portal/target/mall-portal-1.0-SNAPSHOT-exec.jar --spring.config.additional-location=file:./SDC/environment/application-sdc.yml --server.port=18085
```

```sh
rtk proxy java -jar mall-admin/target/mall-admin-1.0-SNAPSHOT.jar --spring.config.additional-location=file:./SDC/environment/application-sdc.yml --server.port=18080
```

portal 用 `-exec.jar`，admin 用普通文件名。看到 Started 后，在第三个终端查询：

```sh
rtk proxy curl --noproxy '*' 'http://127.0.0.1:18085/product/search?keyword=HUAWEI%20P20&pageNum=1&pageSize=5'
```

验收：JSON 的业务 `code` 为200，`data.list` 包含商品26。不要只看 HTTP200。课程配置关闭 RabbitMQ 消费者自动启动，避免浏览商品时消费订单取消消息；因此此运行方式不证明异步订单流程。IDEA 也可运行 `MallPortalApplication` / `MallAdminApplication`，工作目录设 mall，Program arguments 使用对应的两个 `--` 参数。

结束时 Java 终端 Ctrl+C；中间件停止并保留数据：

```sh
rtk proxy docker compose -f SDC/environment/compose.yml stop
```

重开仍用 `up -d`。不要加 `down -v`，它会删除本课程数据卷；需要重做数据库时先备份，由教师指导。已存在数据卷时 SQL 不会重复导入。

## 5. 配套前端安装、配置和运行

先确保第4节 admin/portal 已启动。用编辑器创建本地环境文件，不提交密钥。

**后台前端**：在 `mall-admin-web` 根目录新建 `.env.development.local`，内容一行：

```dotenv
VITE_BASE_SERVER_URL=http://localhost:18080
```

在 **mall-admin-web** 目录运行：

```sh
rtk proxy npm ci
rtk proxy npm run build
rtk proxy npm run dev -- --host 127.0.0.1 --port 5174 --strictPort
```

浏览器打开 `http://127.0.0.1:5174`，样例后台账号 `admin` / `macro123`。打开开发者工具 Network，确认登录请求发往 `localhost:18080/admin/login`，不要发到公网演示站。登录后查看商品列表，只做浏览；若失败，先查后端日志和接口地址，不通过删库重试。

**商城前端**：在 `mall-app-web` 根目录新建 `.env.development.local`：

```dotenv
VITE_API_BASE_URL=http://localhost:18085
VITE_USE_ALIPAY=false
```

在 **mall-app-web** 目录运行：

```sh
rtk proxy npm ci
rtk proxy npm run build:h5
rtk proxy npm run dev:h5 -- --host 127.0.0.1 --port 5173 --strictPort
```

打开 `http://127.0.0.1:5173`，开发者工具切换手机视图；先浏览首页和商品，不下单、不支付。验收 Network 中请求指向18085，记录一次请求 URL、响应字段及后端入口。图片可能依赖外部地址，图片失败不等于商品接口失败。H5 构建输出位于 `dist/build/h5`；后台构建输出位于 `dist`。

两者保留 package-lock，优先 `npm ci`，不要为消除警告擅自执行 `npm audit fix --force`。更改 `.env` 后重启 Vite。浏览器使用上面的 `127.0.0.1` 地址，与启动绑定地址一致；`localhost` 可能优先解析为 IPv6，误连到另一个已有服务。本次实际使用 Node26 构建通过；Node22符合后台声明的兼容范围，但本次未另做 Node22 的构建复测。样式弃用、打包体积警告须与真正的编译错误区分。

## 6. E1–E7 的操作与验收

下列 Maven 命令工作目录统一为 **mall**。`-pl` 选模块，`-am` 连同依赖模块构建；E2/E5 还会执行依赖的 E1 测试。每个实验先读本节，再看对应目录的详细[导航](README.md)。IDEA 测试类均在 `SDC/Ex/src/test/java`，main 演示在 `src/main/java`。

### E1：开发环境与棕地仓库导读

**目标**：解释七个产品模块的职责、依赖与生成代码边界，追踪下单—支付—超时取消。

1. 完成第2–5节，保存版本、构建、商品查询与前端请求证据。
2. 从根 POM 读 modules，再读各模块直接依赖。标出 `mall-mbg` 是生成代码，不修改它。
3. 运行 `MallFacts.main`，对照输出和源码，浏览 `SDC/E1/diagrams` 的HTML图。
4. 在 IDEA 查找 `OmsPortalOrderController` → `OmsPortalOrderServiceImpl` → `PortalOrderDao`，再看 `CancelOrderSender` → RabbitMQ → `CancelOrderReceiver`。逐条写出当前文件和行号，旧文档行号只作线索。
5. 运行测试：

```sh
rtk proxy mvn -pl SDC/E1 -am test
```

**验收/提交**：3项测试通过；模块依赖图、调用链、一次真实商品查询；写清 `/order/cancelOrder` 是投递延迟消息，不能解释成已立即取消。交一项设计疑点与一项自己纠正的理解。

### E2：体系结构建模与方案评价

**目标**：用4+1视图描述系统，比较方案而不是看到依赖就断言“违规”。

1. 运行 `LayerRules.main`，阅读 `SDC/E2/说明.md`。分析取消接口命名、控制器翻译改密返回码、服务层依赖生成查询对象；说明具体维护代价。
2. 绘制逻辑、开发、进程、物理视图，用订单取消场景贯穿“+1”。
3. 比较“结果类型＋查询接口”和“兼容门面＋手写 DAO”，列可测试性、可替换性、改动成本，选一项并写出代价。这里不要求把所有建议都实现。
4. 打开同级 mall-swarm 的根 POM、`mall-gateway` 和 `mall-auth` 配置：解释为什么出现注册/配置中心、网关、独立认证，以及增加了哪些部署依赖。SDC 仍在 mall；不要把两者 `mall-common` 的同坐标产物混装到本机 Maven 仓库。

```sh
rtk proxy mvn -pl SDC/E2 -am test
```

**验收/提交**：E2自身3项通过（连同E1共6项）；4+1视图、证据清单、两方案比较和取舍。源码字面检查通过不证明已经完成解耦。swarm 本课只读，不要求启动 Nacos 或整个微服务群；参考[swarm 原项目说明](https://github.com/meng004/mall-swarm#readme)，其默认局域网地址不可直接照抄。

### E3：规格先行与 AI 结对编程

**目标**：验证消耗积分与赠送积分分别保存，在真实订单插入边界断言。

1. 先写规格：使用积分null/0/30时各存什么；使用30赠送12应满足 `useIntegration=30`、`integration=12`。列出不改接口、表结构、生成代码等约束。
2. 读 `OrderIntegrationTest`，Debug 到真实 `generateOrder` 和 `OmsOrderMapper.insert`；外部依赖由 Mockito 替换，业务方法不能替换成另一套算法。
3. 按第7节运行原版/当前版对照，核对失败是字段值错误而非编译或环境失败。
4. 在个人分支补充自己的边界案例，再让 AI 按规格提出修改，人工核对 diff 并解释保留/拒绝的理由。参考实现已修复，不需为了截图破坏当前主分支。

```sh
rtk proxy mvn -pl SDC/E3 -am test
```

**验收/提交**：4项通过；规格、失败断言、修改差异、当前绿灯、`generateOrder` 方法行/分支覆盖率均≥80%。已有日志不能冒充本人执行或历史测试先行证明。

### E4：设计模式与重构

**目标**：判断策略模式是否适合促销分支，确保重构前后行为一致。

1. 读 `PromotionTest` 的7组行为案例，列金额、文案、库存、赠送积分和成长值期望；满减案例金额3.3000。
2. 对照原版 `OmsPromotionServiceImpl` 与当前策略实现，说明公共接口为什么不需要变化。
3. Debug `calcCartPromotion`，从促销类型走到具体策略。写出增加一种促销前后分别改哪些地方。
4. 按第7节对原版和当前版跑同一测试；原版E4本来就应通过，这是特征测试，不以原版失败作为目标。

```sh
rtk proxy mvn -pl SDC/E4 -am test
```

**验收/提交**：1个JUnit方法内7组行为通过；模式名称/问题/方案/效果四要素、类关系图、前后对照，说明新增结构的成本。

### E5：变更影响分析

**目标**：先确定低库存预警应改哪里、会影响什么，再进入E6实现。

1. 运行 `StockImpact.main`，区分商品表库存与 SKU 的 `stock`、`lockStock`、`lowStock`。
2. 沿下单锁定、支付扣减、取消释放、退货及后台编辑查实际 SQL 和调用者；不要只搜索一个字段就得出全局结论。
3. 写改动文件、受影响调用链、回归范围和不可变约束；至少排除一个不合适方案并说明原因。

```sh
rtk proxy mvn -pl SDC/E5 -am test
```

**验收/提交**：E5自身3项通过（连同E1共6项）；影响图、变更计划、风险及验证办法。本实验不实现预警；静态工具帮助定位，不证明并发或事务正确。

### E6：规格驱动的需求变更

**目标**：将低库存预警写成可测试规格，保持原交易返回语义。

1. 承接E5：可售库存为 `stock-lockStock`；严格低于 SKU 的 `lowStock` 才告警；等于/阈值null不告警。
2. 读 `StockWarningTest`，列出4<5、5=5、null阈值、告警读取失败的预期；阅读实际 `paySuccess` 和 `warnSku`。
3. Debug 测试，观察支付返回值和日志；日志必须包含 sku id、可售、阈值，不包含会员信息。
4. 写用户故事、验收准则、非功能要求、接口兼容说明；结合第7节核对原版缺失告警与当前通过。

```sh
rtk proxy mvn -pl SDC/E6 -am test
```

**验收/提交**：2项通过；严格阈值、缺失值、读取异常和交易返回值证据。预警不能拒绝成功交易，不能额外扣库存；单元测试不证明真实事务或并发正确。

### E7：只读 AI 功能接入与验收

**目标**：比较统一 `ProductQueryService` 下普通/LLM两种实现，理解模型只解析意图、数据库提供事实。

1. 阅读 `mall-portal/query` 与 `llm`：`ExistingProductQueryService`、`LlmProductQueryService`、`LlmClient`。画出“文本→受限条件→校验→真实SQL→商品摘要”的调用图。

```sh

```

预期16项：查询8、SDK3、评测器2、Cursor进程协议3。它们不调用在线模型，不是准确率证据。SDK测试需要系统允许本机 HTTP 监听。

3. 启动第4节中间件。IDEA 运行 E7 的 `QueryDemo.main`，classpath选 E7，工作目录设 **mall**，Program arguments 填 `existing 小米`，环境变量填：


4. 配置一种模型路径，改程序参数为 `llm "查询名称包含小米且价格小于3000的商品"`：

| 路径 | IDEA 环境变量 | 前置条件 |
|---|---|---|
| LangChain4j API | `LLM_PROVIDER=openai-compatible`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`或`LLM_ACCESS_TOKEN`二选一 | 使用目标服务实际接受的OpenAI-compatible端点及凭据 |
| 本机 Cursor | `LLM_PROVIDER=cursor`、`LLM_MODEL=grok-4.7-high-fast` | 安装官方CLI并通过 `cursor-agent login` 登录；模型可按账号权限替换；需要RTK |

凭据只放个人IDE环境变量，不写源码、截图或提交记录。Cursor复用官方CLI保存的登录态，无需提取 token，也不能把 IDE token 填到其他厂商 API。安装与登录见[Cursor官方CLI](https://cursor.com/docs/cli/overview)和[认证说明](https://cursor.com/docs/cli/reference/authentication)。`LlmClient` 隔离接入方式；不支持的厂商协议需要适配，不能承诺任意服务只改URL就兼容。

5. 核对名称包含、价格严格低于、库存严格少于、AND组合。`%`/`_`按字面名称处理；非法JSON和范围外请求返回 `UNSUPPORTED`，访问失败返回 `UNAVAILABLE`。不支持写操作、SQL、任意工具和自动执行模型生成代码；没有库存草稿/确认/撤销。本版不展示模型自报置信度。


先按课程平台要求交分支/补丁或仓库链接。学生没有教师仓库写权限是正常现象；如需在线提交，在自己的 GitHub 账号 fork 教师仓库后推送自己的仓库，不请求修改教师仓库权限。个人分支既保留参考实现，又记录自己的工作，报告必须指出哪些改动是自己完成的。

| 现象 | 排查与处理 |
|---|---|
| invalid target release / class version | 检查 `mvn -version` 的Java版本与IDE Runner，不只检查 `java -version` |
| 找不到SDC模块/依赖 | 确认教学分支、工作目录mall、使用根POM与 `-am` |
| 测试为0或全部Skipped | 去掉命令行 `-DskipTests=true`，检查选的是SDC模块 |
| Maven首次离线失败 | 去掉 `-o`，联网准备依赖；这是环境失败，不是缺陷红灯 |
| Docker连接失败/端口占用 | 启动Docker Desktop；检查其他程序，别关闭不属于自己的服务；改端口须同时改课程YAML |
| MySQL未知表/连接拒绝 | 看Compose日志等待初始化；确认用了课程配置，不是默认3306 |
| 前端请求仍到8080/8085 | 确认文件名 `.env.development.local` 和变量拼写，重启Vite，检查Network |
| 登录失败 | 使用独立样例库的 admin/macro123；不要把商城会员账号与后台管理员混用 |
| E7 UNAVAILABLE | 检查模型权限、网络、凭据或官方CLI登录；不把不可用计为正确拒绝 |
| E7 UNSUPPORTED | 看是否超范围或模型输出不符合协议，保留结果，不删失败题凑分 |
| 原版对照找不到提交 | 使用完整clone；必要时从教师仓库取回历史，不能用编译错误充当失败测试 |
