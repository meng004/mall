# E5-04 只清除指定日期以前的浏览记录：影响分析

分支 `exp/e5-04`，基线 `baseline-dcaa93b3`。本示例只做影响分析并锁定现状，不改产品代码，不实现按截止时刻清理。对照结果见 [evidence/compare.txt](evidence/compare.txt)。

## 需求与边界

新增独立的按截止时刻清理操作：只删除当前会员、`createTime` 严格早于截止时刻的记录；原"全部清空"保留。截止时刻须带时区偏移量，精度到毫秒，与 `Date` 字段一致。

## 现状与调用链

```
POST /member/readHistory/clear
  MemberReadHistoryController.clear              controller/MemberReadHistoryController.java:52-57
    MemberReadHistoryServiceImpl.clear           service/impl/MemberReadHistoryServiceImpl.java:81-84
      memberService.getCurrentMember()           会员来自登录态，不是请求参数
      MemberReadHistoryRepository.deleteAllByMemberId   repository/MemberReadHistoryRepository.java:21（Mongo 派生删除）
GET /member/readHistory/list
  MemberReadHistoryServiceImpl.list  74-78 → findByMemberIdOrderByCreateTimeDesc（Repository 16 行）
```

`MemberReadHistory.createTime` 是 `Date`（`domain/MemberReadHistory.java:31`）。列表按会员和创建时间倒序分页，与删除条件无关。收藏、品牌关注也有各自的 `deleteAllByMemberId`，与本需求无关。

## 锁定现状的测试

[SDCE504Test](../../../../mall-portal/src/test/java/com/macro/mall/portal/sdc/SDCE504Test.java) 用真实服务、会员 101、Mock Repository：

- `clear()`：调用 `deleteAllByMemberId(101L)`（46 行），未调用无会员条件的 `deleteAll()`（47 行）。
- `list(1, 5)`：捕获 memberId=101、页码 0、大小 5（53-55 行）。

运行前预测与观察一致。测试不断言"不存在 clearBefore"，以免新需求实现后被误当成永久规格。

## 改动文件清单

| 文件 | 改／不改 | 理由 |
|---|---|---|
| `MemberReadHistoryController` | 改 | 新增 `POST /member/readHistory/clearBefore?before=`；解析为 `OffsetDateTime` 再转 `Instant`；无偏移或小数超过毫秒且非零则拒绝，不截断 |
| `MemberReadHistoryService` 及实现 | 改 | 新增 `clearBefore(Instant)`，会员仍取自 `getCurrentMember` |
| `MemberReadHistoryRepository` | 改 | 新增 `deleteByMemberIdAndCreateTimeBefore(Long, Date)`，会员与 `createTime < cutoff` 在同一次删除中 |
| 旧 `clear`、`list` 及其 Repository 方法 | 不改 | 需求保留原清空，不改变查询 |
| `MemberReadHistory` 文档模型 | 不改 | `createTime` 已存在 |

## 回归范围

| 输入 | 期望 | 状态 |
|---|---|---|
| 现有 clear，会员 101 | 只按会员删除 | 已锁定 |
| 现有 list | 会员范围、倒序分页不变 | 已锁定 |
| 101 有 t−1ms、t、t+1ms，202 有 t−1ms | 只删 101 的 t−1ms，返回 1；恰等于 t、晚于 t、其他会员保留 | 计划，需隔离 Mongo 证明条数 |
| `+08:00` 与 `Z` 表示同一瞬间 | 删除集合相同 | 计划 |
| 无匹配 | 返回 0 | 计划 |
| 无偏移、无法解析、亚毫秒非零 | 输入错误，不调用删除 | 计划，控制器单测 |

## 被排除的方案

- 给现有 `clear` 加可选时间参数：调用方分不清"全删"与"删一部分"，参数缺失时有误删风险。
- 在服务里先查再逐条删除：会员条件和时间边界不在一次 Repository 删除里，记录多时还要分页。
- 按本地墙钟字符串比较：时区不同会删错范围。

## 风险

按触发顺序：先拒绝非法时间与亚毫秒截断，再保证会员条件进入删除（漏掉会误删其他会员），最后核对 `<` 而不是 `<=`（等于截止时刻的记录必须保留）。
