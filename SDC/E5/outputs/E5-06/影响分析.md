# E5-06 首页人气推荐批次去重：影响分析

分支 `exp/e5-06`，基线 `baseline-dcaa93b3`。本示例只做影响分析并锁定现状，不改产品代码，不实现去重。对照结果见 [evidence/compare.txt](evidence/compare.txt)。

## 需求与边界

输入为非空有效商品 ID。同一次 `create` 中重复的 `productId` 只保留首次出现的记录（含其名称），返回本次 Mapper 实际插入数之和。空列表返回 0。异常原样抛出，沿用项目事务行为。不承诺跨请求或并发唯一，不加唯一索引，不做幂等平台。

## 现状与调用链

```
POST /home/recommendProduct/create  (List<SmsHomeRecommendProduct>)
  SmsHomeRecommendProductController.create         controller/SmsHomeRecommendProductController.java:27-35
    SmsHomeRecommendProductService.create          service/SmsHomeRecommendProductService.java:16-17（@Transactional）
      SmsHomeRecommendProductServiceImpl.create    service/impl/SmsHomeRecommendProductServiceImpl.java:22-30
        循环：recommendStatus=1、sort=0、recommendProductMapper.insert；返回 list.size()
```

- 控制器 `count > 0` 才返回成功。本仓库 `create` 的调用方只有该控制器。
- 同服务的 `list`、`delete`、`updateSort`、`updateRecommendStatus` 不处理这批输入。
- 表 `sms_home_recommend_product`（`document/sql/mall.sql:2111-2117`）主键只有 `id`，`product_id` 可空且无唯一约束。

## 锁定现状的测试

[SDCE506Test](../../../../mall-admin/src/test/java/com/macro/mall/sdc/SDCE506Test.java) 测真实服务，只 mock Mapper，在 `insert` 接到参数的当时复制。4 项均锁定当前行为：

- 输入商品 7 FIRST、7 SECOND、8 EIGHT：`insert` 3 次（39 行），默认状态 1、排序 0，返回 3。
- Mapper 返回 0 时，两条输入仍返回 2（返回值是列表长度）。
- 空列表返回 0 且不插入。
- Mapper 抛出的 `IllegalStateException` 原样传出。

运行前预测与观察一致。插入 3 次和"返回 2"是现状，不是去重已通过；E6 实现后这两项会改变，届时由 E6 示例自己的测试接替，本示例不承担。

## 改动文件清单

| 文件 | 改／不改 | 理由 |
|---|---|---|
| `SmsHomeRecommendProductServiceImpl.create` | 改 | 唯一落点。`LinkedHashMap` 按 `productId` `putIfAbsent` 保留首次顺序，沿用默认状态与排序，累加每次 `insert` 返回值 |
| `SmsHomeRecommendProductService` | 不改 | 签名不变，`@Transactional` 保留 |
| 控制器 | 不改 | 仍用 `count > 0`，只是 count 变成真实插入数 |
| 表结构、`mall-mbg` | 不改 | 需求不含跨请求唯一 |
| 列表、删除、排序、状态接口 | 不改 | 不处理批量创建输入 |

## 回归范围

| 输入 | 期望 | 状态 |
|---|---|---|
| 7 FIRST、7 SECOND、8 EIGHT | 现状插入 3 次 | 已锁定 |
| 同样输入的新规则 | 只插 FIRST 与 EIGHT，顺序不变 | 计划 |
| 默认字段 | 状态 1、排序 0 | 已锁定，新规则下须保持 |
| 空列表 | 0，无插入 | 已锁定 |
| 两条插入分别返回 1 和 0 | 返回 1 | 计划；现状返回 2 |
| Mapper 抛异常 | 不吞、不改写成成功 | 已锁定 |

## 被排除的方案

- 给 `product_id` 加唯一索引：要改表、处理历史重复行，且需求只要求单次请求内去重。
- 幂等令牌或去重框架：超出需求；一次请求内的首次出现用标准库 `LinkedHashMap` 即可表达。
- 用 `HashSet` 去重：丢失输入顺序，"保留首次"不再可验证。

## 风险

1. 返回值仍用列表长度：Mapper 返回 0 或去重后条数减少时虚报成功。
2. 捕获并吞掉异常：事务代理不再按运行时异常回滚，部分插入可能残留。
3. 并发：表无唯一约束，两个并发请求仍可各插入同一商品；本题不宣称并发唯一。
