# E5-05 收藏列表增加商品名筛选：影响分析

分支 `exp/e5-05`，基线 `baseline-dcaa93b3`。本示例只做影响分析并锁定现状，不改产品代码，不实现筛选。对照结果见 [evidence/compare.txt](evidence/compare.txt)。

## 需求与边界

收藏列表增加可选关键字，对收藏快照里的商品名做字面包含匹配；空关键字维持原列表；不实时联查商品表。

## 现状与调用链

```
GET /member/productCollection/list?pageNum&pageSize
  MemberProductCollectionController.list         controller/MemberProductCollectionController.java:50-56
    MemberCollectionService.list(pageNum, pageSize)   service/MemberCollectionService.java:24
      MemberCollectionServiceImpl.list           service/impl/MemberCollectionServiceImpl.java:67-71
        getCurrentMember → PageRequest.of(pageNum-1, pageSize)
        MemberProductCollectionRepository.findByMemberId   repository/MemberProductCollectionRepository.java:26（Mongo）
```

名称在快照字段 `MemberProductCollection.productName`（`domain/MemberProductCollection.java:27`），由 `add`（服务 33-57 行）写入 Mongo，不是列表时从商品表读取。

## 锁定现状的测试

[SDCE505Test](../../../../mall-portal/src/test/java/com/macro/mall/portal/sdc/SDCE505Test.java) 调用真实服务 `list(2, 5)`，在 Repository 接到参数的当时捕获：会员 101（51 行）、页码 1、大小 5（52-53 行）；服务原样返回替身给出的同一 Page（54 行）。运行前预测与观察一致。测试不断言"尚未过滤"，以免新需求实现后被误当成永久规格。

## 改动文件清单

| 文件 | 改／不改 | 理由 |
|---|---|---|
| `MemberProductCollectionController.list` | 改 | GET 增加可选 `keyword`；不新增路径，旧请求不传即可 |
| `MemberCollectionService` | 改 | 新增三参数 `list`；两参数保留并委托，不复制查询 |
| `MemberCollectionServiceImpl.list` | 改 | 空关键字仍走 `findByMemberId`；否则 `Pattern.quote(keyword)`，不忽略大小写 |
| `MemberProductCollectionRepository` | 改 | 新增 `findByMemberIdAndProductNameRegex(Long, String, Pageable)`，筛选与分页、计数在同一次查询中 |
| 商品 Mapper、MySQL | 不改 | 数据源是 Mongo 快照 |
| `add`、`delete`、`detail`、`clear` | 不改 | 不涉及列表筛选 |

## 回归范围

| 输入 | 期望 | 状态 |
|---|---|---|
| 两参数 list | 会员 101、页码换算、原样返回 Page | 已锁定 |
| 空／空白关键字 | 与两参数 list 相同，仍走 `findByMemberId` | 计划 |
| 普通字 | 快照名大小写敏感的字面包含 | 计划 |
| `.`、`*` 等正则特殊字符 | 按字面匹配：`.` 命中 `a.b`，不命中 `axb` | 计划，需隔离 Mongo 复核 |
| 匹配项在未过滤时的第二页（pageSize=1） | 过滤后第一页返回它，总数为过滤后的总数 | 计划，需隔离 Mongo |
| 其他会员同名收藏 | 不返回 | 计划 |

建议集成数据：会员 101 有 `a.b`、`axb`、`star*`，未过滤时 `a.b` 在第二页；会员 202 另有 `a.b`。只删除本次插入的 `_id`。

## 被排除的方案

- 联查商品表 `LIKE`：列表读的是 Mongo 快照，需求明确不实时联查。
- 把用户文本直接当正则：`.`、`*` 放大匹配，非法正则还会抛错。
- 取一页后在 Java 里过滤：跨页丢失命中项，总数错误。

## 风险

按触发顺序：未转义正则 → 漏掉会员条件（泄露其他会员收藏）→ 计数与分页条件不一致 → 空关键字误入 regex 改变旧列表。
