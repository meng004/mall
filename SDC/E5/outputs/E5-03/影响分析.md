# E5-03 收货地址邮政编码规则：影响分析

分支 `exp/e5-03`，基线 `baseline-dcaa93b3`。本示例只做影响分析并锁定现状，不改产品代码，不实现邮编规则。对照结果见 [evidence/compare.txt](evidence/compare.txt)。

## 需求与边界

教学场景限定国内地址。邮编可空；用 `String.strip()` 去掉两端空白后，非空值必须是六位 ASCII 数字。新增时 null 原样保留；更新时未传或 null 不覆盖旧值；纯空白写成 `""`。只约束新写入，不迁移旧行。格式合法不等于地址真实，不增加行政区或街道校验。

## 现状与调用链

```
POST /member/address/add          UmsMemberReceiveAddressController.add     27-35
POST /member/address/update/{id}  UmsMemberReceiveAddressController.update  49-57
  UmsMemberReceiveAddressServiceImpl.add     26-30  设置 memberId → addressMapper.insert
  UmsMemberReceiveAddressServiceImpl.update  41-60  defaultStatus=1 时先清旧默认（57 行），再 updateByExampleSelective（59 行）
    UmsMemberReceiveAddressMapper.xml  insert 108-119 始终写 post_code；updateByExampleSelective 209-211 仅 postCode != null 时写
      ums_member_receive_address.post_code varchar(100)   document/sql/mall.sql:2839
读方：OmsPortalOrderServiceImpl 200-203  getItem 后把已存邮编抄入订单 receiverPostCode
```

服务不读 `postCode`，原样交给 Mapper。模型 `UmsMemberReceiveAddress.postCode` 是 `String`（`mall-mbg/.../model/UmsMemberReceiveAddress.java:20`），XML 10 行映射为 VARCHAR。

## 锁定现状的测试

[SDCE503Test](../../../../mall-portal/src/test/java/com/macro/mall/portal/sdc/SDCE503Test.java) 用真实服务加 Mock Mapper，在回调当时复制 `postCode`：

- 新增 `"001234"`：insert 收到 `"001234"`，`memberId` 为 101（59-60 行）。
- 更新地址 11、`defaultStatus=0`：selective 更新收到 `"001234"`（76 行），不进入清旧默认分支。
- 字段是 `String`，建表语句含 `` `post_code` varchar(100) ``，XML 为 VARCHAR（81-85 行）。

运行前预测与观察一致。测试只锁定合法六位原值，没有断言 5 位、7 位、全角"现在仍能写入"，因为这些现状会被新规则改变，不能当永久断言。

## 改动文件清单

| 文件 | 改／不改 | 理由 |
|---|---|---|
| `UmsMemberReceiveAddressServiceImpl` add／update | 改 | 两个写入入口的交点；调用同一个私有规范化方法，且在任何 Mapper 写入之前执行 |
| 控制器 | 不改 | 只转交请求体，不该有第二套规则 |
| 生成模型 setter | 不改 | MBG 会覆盖；模型分不清"新增保留 null"与"更新未传" |
| Mapper XML、表结构 | 不改 | 已是 VARCHAR；selective 更新的 null 跳过正是"未传不覆盖"所需 |
| `OmsPortalOrderServiceImpl` | 不改 | 只读地址；旧行读出什么就抄什么 |

## 回归范围

| 输入 | 新增 | 更新 | 状态 |
|---|---|---|---|
| `"001234"`（含前导零） | 保持 `"001234"` | 保持，会员条件仍在 | 已锁定 |
| null／未传 | 保留 null | 传给 Mapper 仍为 null，旧值保留 | 计划 |
| `"   "` | `""` | `""`（清空旧邮编） | 计划 |
| `" 001234 "` | `"001234"` | `"001234"` | 计划 |
| 5 位、7 位、全角 `００１２３４` | 拒绝，不调用 insert | 拒绝，不调用任何 update | 计划 |
| 非法邮编且 `defaultStatus=1` | — | 拒绝发生在清旧默认之前 | 计划 |
| 库中已有非规范邮编 | 不迁移 | 未传邮编时不覆盖 | 代码审查 |

样本行 `mall.sql` 2850-2854 的邮编都是 `'518000'`，本题也不做迁移。

## 被排除的方案

- 改生成模型：MBG 重新生成会覆盖，且模型不知道调用是新增还是更新。
- 改成整数列：`001234` 丢失前导零。
- 只改控制器：服务才是两个写入入口的交点，其他调用方会绕过。
- 迁移旧数据：改写历史数据，超出"只约束新写入"。

## 风险

1. 校验晚于清旧默认：非法邮编会先改掉当前会员的默认地址再拒绝。
2. null 与空白混同：更新未传字段会清空旧邮编。
3. 数值转换（如 `Integer.parseInt`）丢前导零，或接受全角数字。
4. 订单仍会抄写旧行的原文本：这是读旧数据，不是校验漏洞。
