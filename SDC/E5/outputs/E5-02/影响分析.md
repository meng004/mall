# E5-02 品牌列表的可选厂家筛选：影响分析

分支 `exp/e5-02`，基线 `baseline-dcaa93b3`。本示例只做影响分析并锁定现状，不改产品代码，不实现筛选。对照结果见 [evidence/compare.txt](evidence/compare.txt)。

## 需求与边界

增加可选 `factoryStatus`：不传保持旧结果；`0`、`1` 与现有关键字、展示状态做 AND，并在分页前进入查询；`2` 等非法值按参数错误拒绝且不查库。旧 HTTP 请求与旧四参数 `listBrand(String, Integer, int, int)` 都要继续可用。不改表，不改生成模型，不改商品服务。

## 现状与调用链

- `listBrand` 在本仓库的调用方只有上述控制器；`listAllBrand` 和 `mall-demo` 的同名方法不走这条路径。
- 字段已在写但列表不能按它查：同类 `updateFactoryStatus`（105-112 行）按 id 批量改 `factoryStatus`。
- 存储：`pms_brand.factory_status`（`document/sql/mall.sql:892`），模型 `PmsBrand.factoryStatus`（`mall-mbg/.../model/PmsBrand.java:17`），条件方法 `PmsBrandExample.andFactoryStatusEqualTo`（377 行）。

## 锁定现状的测试

[SDCE502Test](../../../../mall-admin/src/test/java/com/macro/mall/sdc/SDCE502Test.java) 调用真实服务的四参数入口，只 mock `PmsBrandMapper`，在 select 当时复制条件。`listBrand("华为", 1, 2, 5)`：53 行确认条件中没有 `factory_status`；54-60 行确认同一 Criteria 上有 `name like %华为%`、`show_status = 1`，排序 `sort desc`，select 时分页已是第 2 页、每页 5 条。运行前预测与观察一致。这只说明厂家条件尚不存在，不是新功能通过。

## 改动文件清单

| 文件 | 改／不改 | 理由 |
|---|---|---|
| `PmsBrandController.getList` | 改 | 增加可选同名参数，缺省为 `null`，旧请求不变 |
| `PmsBrandService` | 改 | 新增五参数重载；四参数保留 |
| `PmsBrandServiceImpl.listBrand` | 改 | 四参数委托五参数并传 `null`，查询只写一处；先校验非法值，再 `startPage`，再加条件 |
| `mall-mbg`、表结构 | 不改 | 列、模型、Example 条件方法都已存在 |
| `updateFactoryStatus` | 不改 | 那是批量改状态，不是列表条件 |
| `mall-search`、`PmsProductServiceImpl` | 不改 | 品牌列表读 MySQL 品牌表，不是 `EsProduct` |

## 回归范围

| 输入 | 期望 | 状态 |
|---|---|---|
| 旧四参数，不传厂家 | 维持现有条件与 `sort desc` 分页 | 已由 SDCE502Test 锁定 |
| 五参数 `null` / HTTP 不带参数 | 与旧四参数相同，条件里没有 `factory_status` | 计划 |
| `0` 或 `1`，叠加 keyword、showStatus | 同一 Criteria 增加 `factory_status = 0/1` | 计划 |
| `2` | 项目参数错误，不调用 `startPage` 和 `selectByExample` | 计划 |
| 组合筛选的真实分页结果 | 页大小与总数基于过滤后的行 | 需要隔离库，本次未验证 |

## 被排除的方案

- 新增查询对象封装三个条件和分页：调用方要改成构造对象，旧四参数仍需适配；只多一个可选整数，新类型不减少分支。
- 取一页后在 Java 里过滤：页大小和总数都会错。
- 直接修改四参数签名：破坏原服务方法的兼容性。

## 风险

1. 缺省被当成 `0`：旧请求结果改变。
2. 非法值仍查库，或校验放在 `startPage` 之后：PageHelper 的分页线程变量会遗留给下一次查询。
3. 页后过滤：分页总数错误。
