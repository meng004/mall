## 目标

找出库存被改写的调用链，写明不能改什么、排除了哪条方案、回归测哪里。

## 前置条件

JDK 17、Maven。IDEA 打开 `mall/pom.xml`，Project SDK 和 Maven Runner JRE 均选 JDK 17；不需要 Docker。

## 核心步骤

1. 运行：

```bash
rtk proxy mvn -f mall/pom.xml -pl SDC/E5 -am test
```

2. 对照 `SDC/E5/说明.md` 里的变更计划。计划中的旧行号仅作历史定位；当前行号由 Java 演示输出，测试不冻结仓库源码行号。


## 当前 Java 入口

测试命令从包含 `mall` 的工作区运行；若已经在 `mall`，去掉 `-f mall/pom.xml`。首次构建允许 Maven 下载依赖，缓存齐备后可加 `-o`。

IDEA 打开 `SDC/E5/src/test/java` 下的 `StockImpactTest` 运行 JUnit；打开 `src/main/java/com/macro/mall/sdc/e5/StockImpact.java` 运行 `main`，在解析/定位方法设断点。演示会读取当前仓库并输出结果；JUnit 使用临时受控文件验证行为。

`main` 从工作目录向上查找含 `pom.xml` 与 `mall-portal` 的 mall 根目录，也支持工作区下的 `mall`。IDEA 工作目录可选 mall 或实验目录；任意目录启动时在 VM options 设置 `-Dmall.root=/你的路径/mall`（也接受 E 模块目录）。E2/E5 通过 Maven 依赖复用 E1 工具，IDEA 自动加入 classpath。

这些工具只做只读源码辅助检查，不是 Java/SQL 语义分析器：源码匹配依赖字面格式，注释和改名可能影响结果，需人工复核；不能用静态结果证明数据库事务、支付或消息行为。POM 只读项目直接声明依赖，不计算 profile、依赖管理或传递依赖。旧分析中的行号是历史快照。

## 验收标准

- 3 项测试通过。
- 计划包含改动清单、调用链、回归范围、一条被排除的方案，以及最可能出错的地方。
