## 规格

用户故事：作为运营，我希望某个 SKU 的可售库存低于它自己的 `lowStock` 时得到一条预警，以便补货。买家下单和支付的结果不变。

追问后才定下来的：

- 看 SKU 的 `stock - lockStock`，不看商品表库存。
- 阈值用该 SKU 的 `lowStock`，不另设全局常数。
- “低于”是 `<`。等于阈值不预警。
- `lowStock` 为空则跳过，不报错。
- 预警不拒绝下单。

验收准则：

- 可售 4、阈值 5 → 一条预警，含 sku id、可售、阈值。
- 可售等于阈值，或阈值缺失 → 没有预警。
- 预警不额外修改库存；交易本身仍按既有SQL改变库存。

不可变约束：不改 `PortalOrderDao.xml`，不改 `paySuccess` 的返回值，不改 `mall-mbg`。

非功能：

- 可用性：`lowStock` 为空时直接返回；预警读取抛 `DataAccessException` 时记不可用提示，不改变已成功支付的返回值。真正扣库存失败仍按原语义抛出。
- 安全：预警日志只有 sku id、可售数量和阈值，不写会员或密码。

实际数据库事务和并发效果不由单元测试证明。

## IDEA 演示

导入 `mall/pom.xml`，Project SDK 和 Maven Runner JRE 均设为 JDK 17，重新加载 Maven。
打开 `E6/src/test/java/com/macro/mall/sdc/e6/StockWarningTest.java`，点击类旁运行按钮。可在真实 `mall-portal` 业务方法设断点，再 Debug 此测试。测试只替换数据库、Redis、消息等外部依赖，不执行另写的业务副本。

## Maven 复现

以下命令工作目录为 `mall`；先确认 `java -version` 和 `mvn -version` 使用 JDK 17。Maven 首次运行需要网络下载依赖。

```bash
rtk proxy mvn -pl SDC/E6 -am test
```

原项目默认跳过自己的测试；SDC 已启用测试。该命令不要求启动 MySQL、Redis 或消息队列。

## 教师参考分支的原版与当前版综合对照

以下综合命令只在包含E3/E4/E6全部参考实现的教学分支运行；个人练习分支只执行上面的本实验测试，避免被其他未完成实验阻断。

在联网完成一次依赖准备后，Java 工具采用离线 Maven 运行；JaCoCo 依赖首次准备：

```bash
rtk proxy mvn -pl SDC/E3,SDC/E4,SDC/E6 -am org.jacoco:jacoco-maven-plugin:0.8.13:prepare-agent test
rtk proxy java SDC/tools/JavaEvidence.java --original
rtk proxy java SDC/tools/JavaEvidence.java
```

工具在临时目录复制构建所需源码，以原提交的订单/促销服务替换相应文件，运行后清理临时目录。它不回滚工作区。原版预期：E4 通过，E3 两个积分插入断言失败，E6 一个缺失告警断言失败；Maven 编译错误或测试运行错误不视为红灯证据。当前版应全部通过。

日志与当前 JaCoCo XML 写入 `SDC/evidence/java-migration/`。历史运行保留在 `SDC/java-evidence/`，不混用测试计数或覆盖率。新开实验仍应按“规格→失败测试→实现→审查→验证”演示；重建原版不是历史上已执行测试先行的证明。
