# E6 规格驱动的库存预警

当前 Java 入口：`src/test/java/com/macro/mall/sdc/e6/StockWarningTest.java`。以下“本轮”及覆盖率数字属于迁移前历史；新运行记录见 `../evidence/java-migration/`。

## 改动与根因

承接E5，交易引起可售库存下降时，以SKU自己的 `stock - lockStock < lowStock` 判断预警。`generateOrder` 锁库后、`paySuccess` 扣减后调用同一 `warnSku`。等于阈值、缺SKU或缺字段均不告警。取消释放锁定使可售库存增加，不触发低库存通知；后台编辑及退货范围见E5。

原提交有阈值字段却没有预警；旧Python SQL文本重放只证明字符串匹配和模拟计算，不能验证Java日志或交易返回值。本轮直接运行真实订单服务并捕获日志。

还复现了一处实际兼容性缺陷：扣库存成功后，新增的预警查询若抛 `DataAccessException`，旧实现会使支付接口失败，与“预警不改变支付结果”冲突。失败测试在 `java-evidence/e6-warning-read-red.log`。最小修复在统一接缝 `warnSku` 捕获此类查询异常，记无敏感数据的“预警不可用”日志并返回；不吞掉真正扣库存操作的失败，也不改SQL或订单状态处理。

## 接口与规范

`paySuccess` 仍返回 `PortalOrderDao.updateSkuStock` 的更新行数；服务接口、HTTP返回结构、生成Mapper和库存SQL均未改变。取消和退货业务没有随预警一起改写。

同一处 `warnSku` 块缩进：Google Java Style §4.2采用2空格，Oracle旧版Java Code Conventions §4采用4空格。本次保留现有文件的4空格，使补丁局部且便于审查；这只说明缩进口径的取舍，不宣称整个仓库符合Oracle规范。创建新类还是加方法属于设计决策，不再冒充两套编码规范。

来源：[Google Java Style](https://google.github.io/styleguide/javaguide.html#s4.2-block-indentation)、[Oracle Java Code Conventions](https://www.oracle.com/java/technologies/javase/codeconventions-indentation.html)，核对日期2026-10-03。

## 验证与局限

`ExperimentOrderTest` 实际运行 `generateOrder` 与 `paySuccess`。支付测试验证低于/等于/缺阈值、缺SKU、缺库存字段，以及查询异常；检查日志只含SKU、数量、阈值或不可用提示，返回值仍为3，查询预警不修改库存对象。

原提交缺预警的测试失败，本轮7项Java测试全通过。`warnSku` JaCoCo行12/12、分支10/10；调用方覆盖率单独报告，不把本方法100%外推到整个订单流程。见 `java-evidence/original-order.log`、`current.log`、`jacoco.xml`。

日志是本次运营预警渠道，没有接短信/邮件。真实数据库事务、故障后的数据库连接状态和并发锁库存不在单元测试证明范围；迁移已移除 Python SQL 重放，单元测试不作为真实 SQL 执行证据。
